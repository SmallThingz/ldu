# ldu

- Safe Rust only; application code must forbid unsafe code. Prefer throughput over exact scheduling fairness. Schedule approximately by entries checked per competing subtree, without global breadth-first depth barriers. Hover/navigation focus takes priority without restarting scans or blocking input; preserve parallel metadata batches and bounded work.
- Draw the first terminal frame before filesystem scanning. Keep progress channels bounded and repaint immediately after keyboard actions. Once work settles, stop repeated redraws; late ordering and preview results must still repaint. Size cleanup must drain without rearming idle work.
- Sort scanning and completed entries together by size. Mark scanning entries with a gray, one-cell animated Braille spinner; preserve order within bounded near-size groups. Keep the untouched startup cursor on the first sorted row; accepted selection, navigation, filtering or entry-targeted input permanently switches to tracking selection by stable node ID. Keep sorted directory views warm; hover and navigation must not rebuild or destroy whole-directory collections on the input thread. Never paint unsorted provisional rows on entry.
- Keep the browser minimal: one path header, clickable path breadcrumbs, only `? help` at idle, and the entry list. Path components above the scan root are gray and inactive; the scan root and its descendants are bright and clickable. Do not apply the terminal DIM attribute to header text. Never navigate above the scan root. Narrow headers use a single `…` glyph for omitted path components or the omitted part of a long basename; do not add a separate parent control in the header. Keep separators inactive and use exact painted cell hitboxes.
- Every main browser has a `../` row: normal activation opens the parent or does nothing at the scan root; visual plain-click or Enter toggles all direct entries as a group, including entries hidden by a filter or the hidden-files setting, and Ctrl-click clears the selection. Visual activation clears the filter and reveals hidden entries. Wait for the direct folder listing and select all live direct children with bounded work, including children discovered during the request. Do not repeat range work for size-only publications. If scanning stops before the listing finishes, keep known marks, cancel retained confirmation and show the incomplete-selection notice. Never treat that row as a deletable parent/root target.
- Normal plain clicks open directories on valid release; normal left-drag enters visual mode and selects a range. Right-click enters visual mode and selects the painted row on a valid unmoved release, preserving other marks; right-drag uses the same range-selection rules as left-drag from the original selection state. Right-clicking `../` selects all direct entries, including hidden entries, with bounded work; ordinary left-click keeps its group toggle.
- Show `n queued` while jobs wait, or `deleting…` for active deletion with no waiting jobs; never show a removed count or select hint. The visible `? help` label and the whole `n queued [D]` or `deleting… [D]` status are clickable. Help works while filtering and in visual mode; `[D]` opens the queue outside visual mode and opens batch confirmation in visual mode. Show `n selected` without a Visual label or Escape hint; on hover show `X selected`, and clicking it clears selection and exits visual mode. Put the clickable `[d] delete` action immediately beside the selected count, shortening it to `delete` when space is tight. Retain the normal confirmation flow, including while selection work settles.
- Keyboard navigation leaves up to three visible context rows above and below the cursor, clamped at list ends and in short terminals. The mouse wheel scrolls the viewport while hover keeps the highlight at the pointer row. Once selection follows an entry, live resorts preserve the cursor row within that margin. Mouse hovering leaves the viewport still, and held presses retain their painted rows.
- At widths of at least 96 columns, split the browser and preview 4:3. Preview the selected directory's files and subdirectories with the same row rendering as the main list, including spinners and fractional block size bars without brackets or approximation inequalities. Preview regular text files as plain text. Symlinks show their escaped, wrapped destination path only, without opening the target. Use installed utilities for bounded archive listings; unavailable or failed helpers fall back to file details. PDFs show file details only; do not extract their text. Helpers receive anchored opened files, fixed list/preview arguments, bounded output/time and cancellation, with owned process cleanup before application return, including helpers still waiting to start; never extract files. File reads must be bounded, asynchronous and anchored without following symlinks; discard stale results and stop requests when the pane is hidden.
- Use thin, sharp borders only on dialogs, with concise highlighted keys and actions. Dialogs have a top-right close control using their existing cancellation or dismissal semantics; closing the queue does not cancel queued deletions, and closing `Stopping deletions` exits immediately. Dialog choices are clickable compact buttons. All scrollable dialogs support the mouse wheel and have a right-side scrollbar. Show clickable scrolling arrows and any wheel/page hint on the bottom border only when content overflows. An outside left click and release cancels help, information, the queue, deletion confirmations and quit confirmation; errors, other notices and deletion progress retain explicit dismissal controls. Keep dialogs concise; omit redundant status and separate close-hint rows. Right-click anywhere in the top bar to open `Quit LDU?`; one Yes exits idle or starts the existing wait-for-deletion-and-exit flow without another confirmation. Queue pause still applies. No or the close button cancels that request and restores the previous dialog or browser; pending error reports must remain intact. Keep the normal list unframed.
- Preserve ncdu navigation keys. `d` confirms and enqueues asynchronous FIFO deletion; `n` and Escape cancel confirmation. `D` opens the styled queue outside visual mode. Space pauses waiting work; `d` removes a selected waiting job or cancels the selected active job, and `c` cancels active removal. Shift-Up/Down, `K`/`J`, or mouse dragging reorders waiting jobs. Queue hover selects rows, plain click pauses or resumes waiting work, and right-click removes a waiting job or cancels the active job. Show these controls in a compact two-line queue footer. Drag by stable job identity, never move an active job, and keep edge scrolling and reorder work bounded. Block confirmation while its targets and choices cannot be displayed. Retain an immediate `d`, Enter confirmation through asynchronous target checks; cancellation or invalid targets must invalidate it. Anchor deletion beneath the scan root and reject unsafe replacement paths. Mark queued and active targets and their descendants in both lists; paused work remains marked, and cancelled waiting work clears immediately. Reuse compact queue state rather than adding fields to every scanned entry.
- `v` and `V` enter visual mode and select the current entry (`../` selects all direct entries), or clear marks and leave it when already active. Selection uses stable IDs. Plain movement only moves the cursor; Shift movement extends ranges, and Enter toggles the current row. Normal-mode Shift-Up/Down pages without entering visual mode. Keep mode-specific help separate from common keys. In visual mode, plain clicks toggle. Plain drags add ranges from an unselected origin and remove ranges from a selected origin; resolve the origin’s selection once after earlier queued selection input settles. If the origin disappears before replay, retain its selection state from the press. Ctrl-click deselects a row and Ctrl-drag removes a range. Ctrl takes precedence over Shift. Shift-click adds; Shift-drag starts at the pressed row and adds or removes according to its initial selected state, like plain drag. Capture modifiers at mouse press and autoscroll edge drags. Keep range work bounded and retain its initial ordering across sorts.
- Visual `d`, `D` and Delete require asynchronous identity checks and batch confirmation. A request during pending selection work waits for earlier input to settle while retaining confirmation input for that request; `n` and Escape cancel the request or confirmation while preserving selection. Confirmation leaves visual mode and enqueues the batch in displayed order. Keep an enqueueing dialog open until admission finishes so later confirmations cannot overtake the batch; confirmed deletion workers continue. During admission, `n` or Escape stops only the unqueued remainder, while guarded quit cancels all work. Outside visual mode, `d` targets the current entry and `D` opens the queue.
- Suppress scan work and related errors beneath queued deletion targets. Pause scanner admission and metadata work while deletion is active; resume afterwards. Cancellation is cooperative; reconcile surviving directory contents with a scoped refresh. The first `q` or Ctrl-C while deletion is queued or active stops all scans and refresh scheduling, shows deletion progress, and lets confirmed deletion continue. Exit when it finishes; another Ctrl-C cancels jobs regardless of dialog size. Poll input even at visual capacity or while stopping, count external interrupts, and bound cancellation waiting to one second before restoring the terminal without joining blocked workers. Keep q/Enter confirmation geometry guards. The finishing-deletions dialog shows the full active target, waiting count and active-job removed/known-item total, updated as discovery and removal progress; keep long paths scrollable and actions visible.
- Retry a failed removal once, repairing permissions for permission failures and rescanning a nonempty directory once. Keep the total removal attempts bounded per entry, skip exhausted children during ancestor rescans, and continue all remaining siblings after a final failure. Report only failures that remain after recovery. Detect directory cycles against active ancestor device/inode identities, report their full paths once, and continue siblings without revisiting the cycle during parent rescans.
- Apply successful deletion to the model and ancestor totals incrementally. Do not trigger a full rescan or a persistent success dialog. `r` refreshes only the selected folder and `R` only the current directory; preserve navigation, unrelated entries and global hardlink accounting.
- `/` filters current-directory file and folder names by fuzzy basename matching, without recursion. Match on the ordering worker; keep normal views warm, reject obsolete query results, and clear marks and pending gestures when the query changes.
- Preserve raw filenames and distinguish partial/error totals from accurate totals. Ncdu-style `-o FILE` (`-o -` for stdout) exports the full known hierarchy in ncdu-compatible version 1.2 JSON, with counted own sizes and partial-read markers; avoid recursive call-stack growth for deep trees. Preserve valid JSON and the existing lossy non-UTF-8 output policy. Hardlink aliases export their counted zero bytes; do not invent unavailable inode/device metadata.
- Do not follow symlinks. Normalize redundant dot components and separators without collapsing parent resolution or following a final symlink. Track directory device/inode identities once per scan; skip repeated aliases or cycles with a visible partial-read error and completed spinner. Reuse existing metadata, with no per-file visited-set work. Count allocated blocks by default; preserve apparent sizes and global hardlink deduplication.
- Load simple key=value settings from $XDG_CONFIG_HOME/ldu/config or ~/.config/ldu/config; CLI overrides config, then built-in defaults. Bound configuration reads and validate values with path/line diagnostics. Parse help/version before loading config. Detect terminal color support once; map configured RGB to the supported palette without changing global terminal colors. Mouse disabling must suppress capture and all mouse input. Normal deletion after a hover actually changed the active entry within mouse_debounce_ms (default 250) holds confirmation for mouse_debounce_delay_ms (default 1250); discard early confirmation instead of retaining it. Keep cancellation immediate. Warning mode (default true) keeps a readable muted red screen and dialog until dismissal, including after the input hold expires. Explain that mouse movement changed the highlighted item before deletion; show the CLI flag and config value that disable the tint. Zero recent-hover window disables the guard; otherwise preserve immediate d/Enter when unarmed. No guard for visual batches or queue controls. Expiry gets one repaint, without idle polling.
- Linux io_uring metadata and initial leaf-unlink batches use safe owned operations on existing filesystem workers, with at most 64 requests in flight and no busy polling. Keep directory enumeration buffered. Probe support once, retain the original threaded blocking paths on unsupported kernels or architectures, and never replay a destructive operation with an unknown completion. Preserve cancellation, anchored descriptors, per-entry retry limits and sibling continuation.
- Keep Unix scanning, deletion and previews descriptor-relative beneath the held scan root, including macOS and BSD. Use no-follow buffered directory streams on those systems; never fall back to reopening a display path. Linux and FreeBSD may retain O_PATH handles. Respect macOS O_EVTONLY I/O policy and other BSD read-permission requirements; report inaccessible anchors rather than weakening identity checks. Non-directory roots without O_PATH retain metadata without opening a device, FIFO or symlink.
- Use kqueue readiness on macOS, FreeBSD, OpenBSD, NetBSD and DragonFly for terminal input and deletion completion. If native setup, registration or waiting fails, retain the remaining deadline and switch to ordinary descriptor waiting (macOS select, BSD poll). No busy polling or extra input thread. kqueue does not execute stat or unlink; filesystem operations stay on bounded workers. Preserve Linux io_uring behavior.
- Archive helpers require safe process-group ownership and anchored descriptor input; enable them only on Linux, macOS, FreeBSD and DragonFly with supported APIs. OpenBSD and NetBSD keep text/file-details fallback. Missing utilities or descriptor paths also fall back without following the original filename.
- Keep Linux release defaults static musl. Local macOS and FreeBSD packaging may use their base-system libraries; retain notices inside the binary. Mach-O notices belong in a linker section before signing, never an appended trailer. Pin FreeBSD startup-object attribution to the actual sysroot. Keep cross-build/header checks distinct from native runtime qualification, and do not claim support for unqualified BSD variants.
- Use project-relative paths for tools and `.tmp` for temporary fixtures. Never signal unrelated processes.
- Root owns compiler runs, release qualification, commits and repository publication during parallel development.
- Measure only after the host is quiet; do not claim universal speed wins from synthetic timings.
- After the latest implementation is frozen and qualified, complete two consecutive fully saturated six-agent adversarial passes with no valid findings. A finding and its fix, or new user requirements, reset the clean-pass count. Interrupted or unsaturated attempts do not count. Keep review results local under `.tmp/reviews/`; never commit them or include them in release assets.
