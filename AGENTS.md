# ldu

- Safe Rust only; application code must forbid unsafe code. Prefer throughput over exact scheduling fairness. Schedule approximately by entries checked per competing subtree, without global breadth-first depth barriers. Hover/navigation focus takes priority without restarting scans or blocking input; preserve parallel metadata batches and bounded work.
- Draw the first terminal frame before filesystem scanning. Keep progress channels bounded and repaint immediately after keyboard actions.
- Sort scanning and completed entries together by size. Mark scanning entries with a gray, one-cell animated Braille spinner; preserve order within bounded near-size groups and keep selection by stable node ID. Keep sorted directory views warm; hover and navigation must not rebuild or destroy whole-directory collections on the input thread. Never paint unsorted provisional rows on entry.
- Keep the browser minimal: one path header, compact `v select` and `? help` hints, and the entry list. Show the selection count and controls while visual mode is active. At widths of at least 120 columns, preview only the selected directory's subdirectories. Use the same row rendering in both panes, including spinners and fractional block size bars without brackets or approximation inequalities.
- Use thin, sharp borders only on dialogs, with concise highlighted keys and actions. Keep the normal list unframed.
- Preserve ncdu navigation keys. `d` confirms and enqueues asynchronous FIFO deletion; `n` and Escape cancel confirmation. `D` opens the styled queue outside visual mode. Space pauses waiting work; `d` removes a selected waiting job or cancels the selected active job, and `c` cancels active removal. Shift-Up/Down or `K`/`J` reorders waiting jobs. Block confirmation while its targets and choices cannot be displayed. Anchor deletion beneath the scan root and reject unsafe replacement paths.
- `v` and `V` toggle visual selection by stable IDs. Plain and Shift arrows add ranges; Enter toggles the current row, and subsequent movement preserves its explicit deselection. In visual mode, plain clicks toggle and plain drags add ranges; Shift-click adds and Shift-drag reverses a range. Capture modifiers at mouse press and autoscroll edge drags. Keep range work bounded and retain its initial ordering across sorts.
- Visual `d`, `D` and Delete require asynchronous identity checks and batch confirmation. A request during pending selection work waits for earlier input to settle; `n` and Escape cancel the request or confirmation while preserving selection. Confirmation leaves visual mode and enqueues the batch in displayed order. Keep an enqueueing dialog open until admission finishes so later confirmations cannot overtake the batch; confirmed deletion workers continue. During admission, `n` or Escape stops only the unqueued remainder, while guarded quit cancels all work. Outside visual mode, `d` targets the current entry and `D` opens the queue.
- Suppress scan work and related errors beneath queued deletion targets while unrelated scans continue. Cancellation is cooperative; reconcile surviving directory contents with a scoped refresh. Guard `q` and Ctrl-C while deletion is queued or active, cancel all confirmed work on the second step, and wait for active removal to stop before terminal restoration.
- Apply successful deletion to the model and ancestor totals incrementally. Do not trigger a full rescan or a persistent success dialog. `r` refreshes only the selected folder and `R` only the current directory; preserve navigation, unrelated entries and global hardlink accounting.
- Preserve raw filenames and distinguish partial/error totals from accurate totals.
- Do not follow symlinks. Count allocated blocks by default; preserve apparent sizes and global hardlink deduplication.
- Use project-relative paths for tools and `.tmp` for temporary fixtures. Never signal unrelated processes.
- Root owns compiler runs, release qualification, commits and repository publication during parallel development.
- Measure only after the host is quiet; do not claim universal speed wins from synthetic timings.
- After the latest implementation is frozen and qualified, complete two consecutive fully saturated six-agent adversarial passes with no valid findings. A finding and its fix, or new user requirements, reset the clean-pass count. Interrupted or unsaturated attempts do not count. Record results in `REVIEW.md`.
