# ldu

- Safe Rust only; application code must forbid unsafe code. Prefer throughput over exact scheduling fairness. Schedule approximately by entries checked per competing subtree, without global breadth-first depth barriers. Hover/navigation focus takes priority without restarting scans or blocking input; preserve parallel metadata batches and bounded work.
- Draw the first terminal frame before filesystem scanning. Keep progress channels bounded and repaint immediately after keyboard actions. Once work settles, stop repeated redraws; late ordering and preview results must still repaint. Size cleanup must drain without rearming idle work.
- Sort scanning and completed entries together by size. Mark scanning entries with a gray, one-cell animated Braille spinner; preserve order within bounded near-size groups. Keep the untouched startup cursor on the first sorted row; accepted selection, navigation, filtering or entry-targeted input permanently switches to tracking selection by stable node ID. Keep sorted directory views warm; hover and navigation must not rebuild or destroy whole-directory collections on the input thread. Never paint unsorted provisional rows on entry.
- Keep the browser minimal: one path header, a visibly two-column `←─` mouse back button, only `? help` at idle, and the entry list. The back button highlights on hover and navigates on click. Normal plain clicks open directories on valid release; visual clicks select. Show `Deleting ... [D]` only while deletion is queued or active; never show a select hint. Long paths show their tail with a leading `..`. Show the selection count and controls while visual mode is active. Keyboard navigation leaves up to three visible context rows above and below the cursor, clamped at list ends and in short terminals. The mouse wheel scrolls the viewport while hover keeps the highlight at the pointer row. Once selection follows an entry, live resorts preserve the cursor row within that margin. Mouse hovering leaves the viewport still, and held presses retain their painted rows. At widths of at least 96 columns, split the browser and preview 4:3. Preview the selected directory's files and subdirectories with the same row rendering as the main list, including spinners and fractional block size bars without brackets or approximation inequalities. Preview regular text files as plain text. Symlinks show their escaped, wrapped destination path only, without opening the target. Use installed utilities for bounded archive listings and PDF text; unavailable or failed helpers fall back to file details. Helpers receive anchored opened files, fixed list/preview arguments, bounded output/time and cancellation, with owned process cleanup before application return, including helpers still waiting to start; never extract files. File reads must be bounded, asynchronous and anchored without following symlinks; discard stale results and stop requests when the pane is hidden.
- Use thin, sharp borders only on dialogs, with concise highlighted keys and actions. Keep the normal list unframed.
- Preserve ncdu navigation keys. `d` confirms and enqueues asynchronous FIFO deletion; `n` and Escape cancel confirmation. `D` opens the styled queue outside visual mode. Space pauses waiting work; `d` removes a selected waiting job or cancels the selected active job, and `c` cancels active removal. Shift-Up/Down or `K`/`J` reorders waiting jobs. Block confirmation while its targets and choices cannot be displayed. Anchor deletion beneath the scan root and reject unsafe replacement paths. Mark queued and active targets and their descendants in both lists; paused work remains marked, and cancelled waiting work clears immediately. Reuse compact queue state rather than adding fields to every scanned entry.
- `v` and `V` toggle visual selection by stable IDs. Plain movement only moves the cursor; Shift movement extends ranges, and Enter toggles the current row. Normal-mode Shift-Up/Down pages without entering visual mode. Keep mode-specific help separate from common keys. In visual mode, plain clicks toggle and plain drags add ranges; Ctrl-click deselects a row and Ctrl-drag removes a range. Ctrl takes precedence over Shift. Shift-click adds and Shift-drag reverses a range. Capture modifiers at mouse press and autoscroll edge drags. Keep range work bounded and retain its initial ordering across sorts.
- Visual `d`, `D` and Delete require asynchronous identity checks and batch confirmation. A request during pending selection work waits for earlier input to settle; `n` and Escape cancel the request or confirmation while preserving selection. Confirmation leaves visual mode and enqueues the batch in displayed order. Keep an enqueueing dialog open until admission finishes so later confirmations cannot overtake the batch; confirmed deletion workers continue. During admission, `n` or Escape stops only the unqueued remainder, while guarded quit cancels all work. Outside visual mode, `d` targets the current entry and `D` opens the queue.
- Suppress scan work and related errors beneath queued deletion targets. Pause scanner admission and metadata work while deletion is active; resume afterwards. Cancellation is cooperative; reconcile surviving directory contents with a scoped refresh. The first `q` or Ctrl-C while deletion is queued or active stops all scans and refresh scheduling, shows deletion progress, and lets confirmed deletion continue. Exit when it finishes; another Ctrl-C cancels jobs regardless of dialog size. Poll input even at visual capacity or while stopping, count external interrupts, and bound cancellation waiting to one second before restoring the terminal without joining blocked workers. Keep q/Enter confirmation geometry guards.
- Apply successful deletion to the model and ancestor totals incrementally. Do not trigger a full rescan or a persistent success dialog. `r` refreshes only the selected folder and `R` only the current directory; preserve navigation, unrelated entries and global hardlink accounting.
- `/` filters current-directory file and folder names by fuzzy basename matching, without recursion. Match on the ordering worker; keep normal views warm, reject obsolete query results, and clear marks and pending gestures when the query changes.
- Preserve raw filenames and distinguish partial/error totals from accurate totals.
- Do not follow symlinks. Count allocated blocks by default; preserve apparent sizes and global hardlink deduplication.
- Use project-relative paths for tools and `.tmp` for temporary fixtures. Never signal unrelated processes.
- Root owns compiler runs, release qualification, commits and repository publication during parallel development.
- Measure only after the host is quiet; do not claim universal speed wins from synthetic timings.
- After the latest implementation is frozen and qualified, complete two consecutive fully saturated six-agent adversarial passes with no valid findings. A finding and its fix, or new user requirements, reset the clean-pass count. Interrupted or unsaturated attempts do not count. Record results in `REVIEW.md`.
